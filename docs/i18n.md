# Internationalisation

## Langues

Cinq : `en`, `fr`, `es`, `pt-BR`, `de` (`src/i18n/languages.ts`). L'anglais est la langue de repli et la source des types (`i18next.d.ts`). Langue de départ, par priorité (`detect.ts`) : `?lang=` dans l'URL (mémorisé puis retiré de la barre d'adresse), choix précédent (`localStorage` clé `lineup-lang`), langues du navigateur, anglais. `<html lang>` est tenu à jour : les nombres et les dates en dépendent.

## Un espace de noms par feature

Fichiers `src/i18n/locales/<langue>/<espace>.json`, tous chargés dans le bundle (`resources.ts`, pas de chargement réseau). Chaque feature édite son propre fichier. On utilise `useT('<espace>')` (clés typées).

| Espace | Usage |
| --- | --- |
| `common` | Coque, navigation, états génériques, connexion |
| `components` | Composants partagés de `src/components` |
| `errors` | Messages d'erreur par code (voir [api-client.md](api-client.md)) |
| `catalog` | Libellés du catalogue en es, pt-BR et de |
| `feed` | Fil des annonces |
| `post` | Page d'une annonce |
| `editor` | Éditeur d'annonce |
| `myPosts` | Mes annonces |
| `guilds` | Annuaire des serveurs |
| `guildProfile` | Profil public d'un serveur |
| `guildManage` | Gestion d'un serveur |
| `claim` | Revendication d'un serveur |
| `userProfile` | Profil public d'une personne |
| `meProfile` | Mon profil |
| `experiences` | Mes expériences |
| `staff` | Console staff |

## Libellés du catalogue

`GET /lineup/catalog` donne chaque entrée avec un libellé `fr` et `en`. `useCatalogLabel()` (`src/api/catalog.ts`) choisit : `fr` et `en` viennent de l'API ; `es`, `pt-BR` et `de` viennent de l'espace `catalog` (clé `<type>.<id>`), avec repli sur l'anglais de l'API, puis sur l'identifiant lui-même. Les fichiers `fr/catalog.json` et `en/catalog.json` sont vides exprès. `catalog.test.ts` vérifie que chaque identifiant du catalogue de test est traduit dans les trois langues locales. Quand le catalogue d'un déploiement contient un nouvel identifiant, ajoutez sa traduction dans `es`, `pt-BR` et `de`.

## Libellés du kit

Les textes des composants du kit (barre du haut, menu utilisateur, menu de thème) viennent de `design-kit/labels/<langue>.json`, chargés par `src/i18n/kitLabels.ts`. Ils ne se dupliquent pas dans nos espaces.

## Test de parité

`src/i18n/locales.test.ts` impose : les cinq langues et tous les espaces existent ; pas de valeur vide ; pour chaque langue, exactement les clés de l'anglais (sauf `catalog`) ; les mêmes marqueurs `{{variable}}` et `<balise>` que l'anglais. Ajouter une clé exige donc de l'écrire dans les cinq fichiers.

## Terminologie

- Français : "vous". Espagnol : "usted". Allemand : "Sie". Portugais du Brésil : "você".
- "Revue manuelle" (côté personne), "étiquettes" (pas "tags" dans le texte français).
- Une condition qui sera vérifiée plus tard par Lineup (`verified_by_lineup`) se dit "Vérification par Lineup prévue". Jamais "vérifié" : rien n'est vérifié pour le moment, le texte d'aide le dit.
- Console staff : la section s'appelle "Vérifications" (file des vérifications), en anglais "Verifications", es "Verificaciones", pt-BR "Verificações", de "Verifizierungen". La route et les clés restent `reviews`.

## Règles de rédaction (`design-kit/DESIGN-SYSTEM.md` §8)

- Simple, précis, court. Dire ce que fait le produit, avec de vraies fonctions et de vrais chiffres.
- Interdits : remplissage marketing ("seamless", "powerful", "unlock", "elevate" et équivalents), questions rhétoriques, triplets pour le rythme, incises avec tirets cadratins. Pas d'emoji.
- Une petite blague est permise sur une impasse (404), jamais dans le texte du produit.
- En cas de doute, écrire le français d'abord, puis adapter chaque langue (pas mot à mot).
- Toute chaîne visible vient des fichiers de langue, dans les cinq langues. Les composants reçoivent leur texte par props ou `labels`, jamais en dur. Exception : le panneau de dev du mock est en anglais.
